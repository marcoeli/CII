# 📜 RCO-2401: Diretriz de Correção Técnica & Compliance (Versão Definitiva)

**Alvo:** App Flutter, Node-RED, Firmware**Versão do Sistema:** 2.4 (Contrato) + 1.2 (UX)**Objetivo:** Eliminar divergências entre Implementação (Código) e Especificação (Docs).

## 1. Regras de Ouro (Arquitetura)

1. **Soberania do Contrato:** O documento `mqtt_topics_V2.4.md` é a autoridade máxima de mensageria.
2. **Soberania da UX:** O documento `app_ui_ux-espec.md` é a autoridade máxima de comportamento.

    - **Regra do Switch:** A UI **nunca** muda estado visualmente sem confirmação do Banco de Dados (`Stream`). O clique apenas envia o comando.
    - **Regra do Offline:** A UI **sempre** exibe dados do Banco Local, aplicando máscara de "Staleness" (opacidade/ícone) se a última atualização for antiga.
3. **DB-First Estrito:**

    - **MQTT** = Sincronizador (Escreve no Banco).
    - **ViewModel** = Leitor (Lê do Banco e notifica UI).
    - **Proibido:** O ViewModel escutar Streams do MQTT diretamente.

* * *

## 2. Ordens de Execução (Tasks)

### 🔴 Backend: Node-RED (Meta Curator)

**Problema:** Violação de propriedade JSON (vínculo pai/filho).**Ação:**

- Alterar a saída do fluxo para usar a chave **`owner_device_id`** no payload de metadados (`meta/resource/{id}`).
- *Referência:* Contrato V2.4, Seção 6.

### 🔵 Mobile: Flutter (Arquitetura & Lógica)

**Task A: Sync Service & DB (Correção de Entrada)**

1. **Parser de Meta:** Atualizar para ler `owner_device_id` (compatibilidade).
2. **Resiliência (Stubbing):** Se receber `state` ou `data` de um `resource_id` desconhecido (sem Meta prévio):

    - **NÃO** descartar o dado.
    - Criar um registro "Stub" (Rascunho) no SQLite para permitir que o dado seja salvo.
    - *Motivo:* Garante que gráficos e status funcionem mesmo se o pacote Meta atrasar.

**Task B: Boot & Conexão (Correção de Surdez)**

1. **Auto-Start:** Injetar a chamada `MqttRepository.refreshDevices()` no listener do `SelectedHomeProvider`.
2. **Escopo:** A assinatura deve ocorrer imediatamente após a validação do contexto `tenant/home`, sem ação do usuário.

**Task C: Repository & Comandos (Correção de Saída)**

1. **Payload V2.4:** Refatorar `sendPumpCommand` e similares para envelopar argumentos em **`params`**.

    - *Correto:* `{ "action": "START", "params": { "force": false } }`

**Task D: UI & ViewModel (Correção de UX)**

1. **Implementar ViewModels:** Criar `PumpViewModel`, `SensorViewModel`, etc.
2. **Lógica Pessimista:**

    - Ao clicar "Ligar", o ViewModel muda o estado interno para `isLoading = true` (spinner no lugar do switch).
    - O ViewModel **não muda** o `isOn` para `true` manualmente.
    - O ViewModel aguarda o banco de dados notificar que o estado mudou (via MQTT -&gt; DB -&gt; Watch).
    - Ao receber o novo estado do banco, `isLoading` vira `false` e o switch atualiza.

### ⚫ Firmware: ESP32 (Estabilidade)

**Ação:**

1. **Anti-Flood:** Remover loop de 100ms. Implementar envio por **Delta** (ex: mudou 1%) ou **Intervalo Fixo** (ex: 5s).
2. **Feedback:** Garantir envio de confirmação em `.../r/{id}/state` imediatamente após atuar o relé.
